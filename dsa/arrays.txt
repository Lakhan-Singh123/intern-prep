Arrays — DSA Intern Prep
========================


CORE PATTERNS
-------------
1. HashMap/HashSet    — O(1) lookup, frequency counting, seen elements
2. Prefix approach    — precompute to answer queries efficiently
3. Kadane's Algorithm — maximum subarray sum in O(n)
4. Two pointer zones  — maintain invariants with low/mid/high pointers
5. Sort first         — sorting often unlocks a simpler O(n) second pass

1. TWO SUM — LeetCode #1
------------------------
Problem: Find indices of two numbers that add up to target.

Approach: HashMap — store each number with its index.
Before adding nums[i], check if (target - nums[i]) already exists.

  public int[] twoSum(int[] nums, int target) {
      HashMap<Integer, Integer> map = new HashMap<>();
      for (int i = 0; i < nums.length; i++) {
          if (map.containsKey(target - nums[i])) {
              return new int[]{map.get(target - nums[i]), i};
          }
          map.put(nums[i], i);
      }
      return new int[]{};
  }

Why put AFTER check: prevents using same element twice.
If target=6 and nums[i]=3, checking before put avoids matching 3 with itself.

Complexity: Time O(n)  Space O(n)
Brute force: Time O(n²) Space O(1)


2. BEST TIME TO BUY AND SELL STOCK — LeetCode #121
----------------------------------------------------
Problem: Find max profit from one buy and one sell (buy before sell).

Key insight: At each step track minimum price seen so far.
No need to find global min and max — min must come before the sell day.

  public int maxProfit(int[] prices) {
      int maxProfit = 0;
      int minPrice = Integer.MAX_VALUE;
      for (int price : prices) {
          minPrice = Math.min(price, minPrice);
          maxProfit = Math.max(maxProfit, price - minPrice);
      }
      return maxProfit;
  }

Complexity: Time O(n)  Space O(1)


3. PRODUCT OF ARRAY EXCEPT SELF — LeetCode #238
-------------------------------------------------
Problem: Return array where answer[i] = product of all elements except nums[i].
No division allowed. O(1) extra space.

Key insight: For each index, answer = (product of everything to its LEFT)
                                    * (product of everything to its RIGHT)
Do two passes — left to right, then right to left.

  public int[] productExceptSelf(int[] nums) {
      int[] result = new int[nums.length];
      Arrays.fill(result, 1);

      int leftProduct = 1;
      for (int i = 0; i < nums.length - 1; i++) {
          leftProduct *= nums[i];
          result[i + 1] = leftProduct;
      }

      int rightProduct = 1;
      for (int i = nums.length - 1; i >= 1; i--) {
          rightProduct *= nums[i];
          result[i - 1] *= rightProduct;
      }
      return result;
  }

Why Arrays.fill(result, 1):
  result[0] is never written in the left pass (no elements to its left → product = 1)
  result[last] is never multiplied in the right pass (no elements to its right → already 1)

Complexity: Time O(n)  Space O(1) extra


4. LONGEST CONSECUTIVE SEQUENCE — LeetCode #128
-------------------------------------------------
Problem: Find length of longest consecutive sequence in O(n). No sorting.

Key insight: Only start counting from the BEGINNING of a sequence.
A number is a sequence start if (num - 1) is NOT in the set.
This ensures each number is visited at most twice → O(n).

  public int longestConsecutive(int[] nums) {
      HashSet<Integer> set = new HashSet<>();
      for (int num : nums) set.add(num);

      int maxLen = 0;
      for (int num : set) {                      // iterate over SET not array
          if (set.contains(num - 1)) continue;   // skip if not sequence start
          int curr = num;
          int len = 1;
          while (set.contains(curr + 1)) {
              curr++;
              len++;
          }
          maxLen = Math.max(maxLen, len);
      }
      return maxLen;
  }

CRITICAL: Iterate over the HashSet, not the original array.
If you iterate over nums and there are duplicate "start" elements,
you redo the full count for each duplicate → O(n²) → TLE.

Complexity: Time O(n)  Space O(n)


5. MERGE INTERVALS — LeetCode #56
-----------------------------------
Problem: Merge all overlapping intervals.

Key insight: Sort by start time. Then for each interval, either:
  - It overlaps with current (nextStart <= currentEnd) → extend end
  - It doesn't overlap → save current, start fresh

Always use Math.max for merged end — don't assume right interval ends later.
Example: [1,10] and [2,6] → merged end = max(10,6) = 10, not 6.

  public int[][] merge(int[][] intervals) {
      Arrays.sort(intervals, (a, b) -> a[0] - b[0]);
      ArrayList<int[]> result = new ArrayList<>();

      for (int i = 0; i < intervals.length; i++) {
          int[] curr = new int[]{intervals[i][0], intervals[i][1]};
          int j = i + 1;
          while (j < intervals.length && curr[1] >= intervals[j][0]) {
              curr[1] = Math.max(curr[1], intervals[j][1]);
              j++;
              i++;
          }
          result.add(curr);
      }
      return result.toArray(new int[result.size()][]);
  }

Common mistakes:
  - arr.add(x) inside loop adds same reference — use new int[]{...} each time
  - arr.toArray() returns Object[] — use arr.toArray(new int[size][])
  - Forgetting Math.max for end → can shrink interval

Complexity: Time O(n log n)  Space O(n)


6. MAXIMUM SUBARRAY (KADANE'S ALGORITHM) — LeetCode #53
---------------------------------------------------------
Problem: Find subarray with largest sum.

Key insight: At each index, choose the better of:
  1. Start fresh subarray from current element
  2. Extend the existing subarray

Start fresh when the running sum is negative — a negative prefix only drags you down.

  public int maxSubArray(int[] nums) {
      int maxSum     = nums[0];
      int currentSum = nums[0];
      for (int i = 1; i < nums.length; i++) {
          currentSum = Math.max(nums[i], currentSum + nums[i]);
          maxSum     = Math.max(maxSum, currentSum);
      }
      return maxSum;
  }

Initialize both to nums[0], not 0 — array can be all negative.
If initialized to 0, you'd return 0 for [-3,-1,-2] instead of -1.

Complexity: Time O(n)  Space O(1)


7. SORT COLORS (DUTCH NATIONAL FLAG) — LeetCode #75
-----------------------------------------------------
Problem: Sort array of 0s, 1s, 2s in-place in one pass.

Three pointer invariant:
  [0, i)   → all 0s  (sorted)
  [i, j)   → all 1s  (sorted)
  [j, k]   → unknown (being processed)
  (k, n-1] → all 2s  (sorted)

  public void sortColors(int[] nums) {
      int i = 0, j = 0, k = nums.length - 1;
      while (j <= k) {
          if (nums[j] == 0) {
              int temp = nums[i]; nums[i] = nums[j]; nums[j] = temp;
              i++; j++;
          } else if (nums[j] == 1) {
              j++;
          } else {
              int temp = nums[j]; nums[j] = nums[k]; nums[k] = temp;
              k--;
              // j does NOT advance — element from k is unknown, recheck it
          }
      }
  }

Key difference between case 0 and case 2:
  Swap with i (low) → j advances because we know a 1 came back from i zone
  Swap with k (high) → j stays because unknown element came from k zone

Complexity: Time O(n)  Space O(1)


================================================================
COMMON MISTAKES TO AVOID
================================================================

1. Comparing Integers with ==
   Integer a = 128, b = 128;
   a == b is false (beyond cache range -128 to 127)
   Always use .equals() for wrapper types

2. ArrayList.add() with same reference in a loop
   arr.add(x)         — every entry points to same x, all change together
   arr.add(new int[]{x[0], x[1]})  — correct, fresh array each time

3. ArrayList to int[][] conversion
   arr.toArray()                      — returns Object[], compile error
   arr.toArray(new int[arr.size()][]) — correct

4. Iterating over array vs HashSet when duplicates matter
   for (int num : nums) — processes duplicates multiple times
   for (int num : set)  — unique values only, use when duplicates cause TLE

5. Kadane's initialization
   int max = 0    — wrong for all-negative arrays
   int max = nums[0]  — correct

6. Merge intervals end
   merged[1] = next[1]              — wrong, can shrink interval
   merged[1] = Math.max(curr, next) — correct
