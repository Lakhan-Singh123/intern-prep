MODULE 3 — PHYSICAL AND DATA LINK LAYER                    ★★
================================================================

PHYSICAL LAYER ★
[ ] Physical Layer — converts bits to signals
[ ] Transmission Media
      Twisted Pair Cable — most common (Cat5, Cat6)
      Fiber Optic Cable  — light signals, long distance, fast
      Coaxial Cable      — older, cable TV
[ ] Full duplex vs Half duplex vs Simplex
      Full: both sides simultaneously (phone call)
      Half: one at a time (walkie-talkie)
      Simplex: one direction only (TV broadcast)

DATA LINK LAYER ★★★
[ ] What is the Data Link Layer? What does it do?
      Framing, MAC addressing, error detection, access control
[ ] MAC Address
      48-bit hardware address (burned into NIC)
      Format: XX:XX:XX:XX:XX:XX (hex)
      OUI (first 3 bytes) = manufacturer
      MAC vs IP — MAC is physical/local, IP is logical/global
[ ] Error Detection
      Parity bit — simplest, detects odd errors
      Checksum — used in TCP/UDP
      CRC (Cyclic Redundancy Check) — most reliable, used in Ethernet
[ ] Medium Access Control (MAC protocols)
      CSMA/CD — Carrier Sense Multiple Access / Collision Detection
        Used in Ethernet (wired)
        Sense before transmit, detect collision, back off and retry
      CSMA/CA — Collision Avoidance (used in Wi-Fi)
[ ] ARP — Address Resolution Protocol                             ★★★
      Problem: I know IP, I need MAC address to send frame
      ARP Request: broadcast "who has IP X?"
      ARP Reply: "I have IP X, my MAC is Y"
      ARP Cache: stores IP→MAC mappings temporarily
      ARP Spoofing attack (security relevance)
[ ] Network Access Control (basics)
[ ] STP — Spanning Tree Protocol ★
      Problem: switches connected in loops → broadcast storms
      STP disables redundant links, keeps one active path
      Elects Root Bridge, blocks non-optimal paths

DEVICES ★★★
[ ] Hub — Layer 1, broadcasts to all ports, no intelligence
[ ] Switch — Layer 2, uses MAC table, sends only to correct port
[ ] Router — Layer 3, uses IP, routes between networks
[ ] Hub vs Switch vs Router — differences table (very frequently asked)

[ ] Physical Topologies
      Bus — single cable, all share, one failure = network down
      Ring — each node connected to next, token passing
      Star — all connected to central switch (most common today)
      Mesh — every node to every other, redundant but expensive
      Tree — hierarchical star, enterprise networks
[ ] Hybrid Topology — combination (star + ring etc.)
[ ] Logical Topologies — how data actually flows (may differ from physical)
[ ] Ethernet Switching — how switches learn MAC addresses
      Switch builds MAC table by observing source MACs
      Flooding: if destination MAC unknown, send to all ports
[ ] VLANs — Virtual LANs                                         ★★★
      Segment one physical network into multiple logical networks
      Traffic isolation without physical separation
      VLAN ID in Ethernet frame header
      Inter-VLAN routing requires a router or Layer 3 switch
[ ] Switching vs Routing
      Switching: Layer 2, same network, uses MAC
      Routing: Layer 3, different networks, uses IP

MODULE 5 — NETWORK LAYER: IP ADDRESSING                    ★★★
================================================================

[ ] Introduction to Network Layer
      Routing packets from source to destination across networks
      Connectionless — each packet routed independently
[ ] IPv4 Introduction
      32-bit address, written in dotted decimal (x.x.x.x)
      ~4.3 billion addresses (exhausted)
[ ] IPv4 Datagram structure
      Version, IHL, TTL, Protocol, Source IP, Destination IP
      TTL — prevents packets looping forever, decremented at each hop
[ ] IP Addressing Modes
      Unicast — one to one
      Broadcast — one to all (255.255.255.255)
      Multicast — one to group
[ ] Private vs Public IP                                          ★★★
      Private: 10.x.x.x | 172.16-31.x.x | 192.168.x.x
      Public: assigned by ISP, routable on internet
      NAT bridges private ↔ public
[ ] Classful Addressing (historical)
      Class A: /8  (0.x.x.x – 127.x.x.x)
      Class B: /16 (128.x.x.x – 191.x.x.x)
      Class C: /24 (192.x.x.x – 223.x.x.x)
      Class D: Multicast, Class E: Reserved
[ ] Subnetting                                                    ★★★
      Divide a network into smaller sub-networks
      Subnet mask: which bits are network vs host
      /24 = 255.255.255.0 = 256 addresses, 254 usable
      Formula: 2^(host bits) - 2 = usable hosts
      Practice: given IP and mask, find network address, broadcast, range
[ ] CIDR — Classless Inter-Domain Routing                         ★★★
      Replaced classful (more flexible)
      192.168.1.0/26 = 64 addresses, 62 usable
      Aggregation: combine smaller blocks into one route (supernetting)
[ ] IPv6 Introduction                                             ★★
      128-bit, written in hex (8 groups of 4 hex digits)
      Solves IPv4 exhaustion
      No broadcast (uses multicast instead)
      Built-in IPSec support
[ ] IPv6 Datagram — simplified header vs IPv4
[ ] IPv6 over IPv4 — tunneling mechanisms (6in4, Teredo)

EXTRA:
[ ] ICMP — Internet Control Message Protocol                      ★★★
      Used for ping, traceroute, error reporting
      Ping: ICMP Echo Request → Echo Reply
      Traceroute: TTL=1,2,3... each router sends ICMP Time Exceeded
[ ] IP Fragmentation — what happens when packet too large for MTU  ★★
      MTU (Maximum Transmission Unit) = 1500 bytes for Ethernet
      Router fragments, destination reassembles
[ ] Loopback address: 127.0.0.1                                   ★★★
[ ] Default gateway — what it is and why needed                   ★★★

MODULE 6 — NETWORK LAYER: ROUTING                          ★★
================================================================

[ ] Router vs Forwarding
      Routing: building the routing table (control plane)
      Forwarding: moving packet from input to output (data plane)
[ ] Routing Tables — how a router decides where to send a packet
      Destination, Subnet Mask, Next Hop, Interface, Metric
      Longest prefix match rule
[ ] Static Routing — manually configured, simple, no overhead
[ ] Dynamic Routing — routers learn routes automatically
[ ] Distance Vector Routing (RIP) ★
      Each router knows distance to neighbors
      Shares table with neighbors, adds hop count
      Slow convergence, max 15 hops
[ ] Routing Loop and Count-to-Infinity Problem ★
      Fix: split horizon, route poisoning, hold-down timers
[ ] Link State Routing (OSPF) ★★
      Each router knows full topology
      Dijkstra's algorithm for shortest path
      Faster convergence than distance vector
[ ] Hybrid Routing (EIGRP) ★
      Cisco proprietary, combines distance vector + link state
[ ] BGP — Border Gateway Protocol ★★
      Routing between autonomous systems (internet backbone)
      Path vector protocol, used by ISPs
      Policy-based routing

MODULE 7 — TRANSPORT LAYER                                 ★★★
================================================================

[ ] Transport Layer Introduction
      End-to-end communication between processes (not hosts)
      Multiplexing via ports
[ ] Ports and Sockets                                             ★★★
      Port: 16-bit number identifying a process (0-65535)
      Well-known: 0-1023 (HTTP=80, HTTPS=443, DNS=53, SSH=22)
      Registered: 1024-49151
      Ephemeral/Dynamic: 49152-65535 (client ports)
      Socket = IP + Port (unique endpoint)
      Connection = (src IP, src port, dst IP, dst port)

UDP — User Datagram Protocol ★★★
[ ] Connectionless — no handshake, no guarantee of delivery
[ ] No ordering, no error recovery
[ ] Header: Source port, Dest port, Length, Checksum (8 bytes only)
[ ] Use cases: DNS, streaming, gaming, VoIP, DHCP
[ ] Why use UDP? — speed, low latency, application handles reliability

TCP — Transmission Control Protocol ★★★
[ ] Connection-oriented — must establish connection first
[ ] Reliable: acknowledgements, retransmission, ordering
[ ] 3-Way Handshake (connection setup)
      SYN → SYN-ACK → ACK
      Why 3 steps? Both sides must confirm send AND receive capability
[ ] 4-Way Handshake (connection teardown)
      FIN → ACK → FIN → ACK
[ ] Sequence and Acknowledgement numbers
      SEQ: byte number of first byte in segment
      ACK: next expected byte from other side
[ ] Flow Control — Sliding Window                                  ★★★
      Receiver advertises window size (rwnd)
      Sender cannot send more than window allows
      Prevents fast sender from overwhelming slow receiver
[ ] Congestion Control                                            ★★★
      Slow Start: begin with cwnd=1, double each RTT
      Congestion Avoidance: linear increase after ssthresh
      Fast Retransmit: 3 duplicate ACKs → retransmit immediately
      Fast Recovery: halve cwnd instead of resetting to 1
[ ] TCP vs UDP — when to choose which                             ★★★

[ ] TCP head-of-line blocking — why HTTP/2 moved to QUIC          ★★
[ ] TIME_WAIT state — why it exists (2*MSL)                       ★★
[ ] Nagle's algorithm — batching small packets                     ★

HTTP ★★★
[ ] HTTP Request-Response Model
      Client sends Request, Server sends Response
      Stateless — each request independent
[ ] HTTP Methods
      GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS
      Safe vs Idempotent methods
[ ] HTTP Status Codes
      1xx: Informational | 2xx: Success | 3xx: Redirect
      4xx: Client Error | 5xx: Server Error
      Know: 200, 201, 204, 301, 302, 304, 400, 401, 403, 404, 405, 500, 503
[ ] HTTP Versions                                                  ★★★
      HTTP/1.0 — new TCP connection per request
      HTTP/1.1 — persistent connections, pipelining (head-of-line blocking)
      HTTP/2   — multiplexing, header compression, binary framing
      HTTP/3   — runs over QUIC (UDP-based), no head-of-line blocking
[ ] HTTP/3 and QUIC
      QUIC = UDP + reliability + TLS built in
      Faster connection setup (0-RTT or 1-RTT)

HTTPS and TLS ★★★
[ ] HTTPS = HTTP + TLS encryption
[ ] TLS Handshake (must know step by step)
      1. Client Hello (supported cipher suites, random)
      2. Server Hello (chosen cipher, certificate)
      3. Certificate verification (CA chain)
      4. Key exchange (Diffie-Hellman or RSA)
      5. Session keys derived
      6. Finished — encrypted communication begins
[ ] Symmetric vs Asymmetric in TLS
      Asymmetric for key exchange, symmetric for data (speed)
[ ] Forward Secrecy — new session key every time, past sessions safe

Web Auth ★★★
[ ] Cookies — small data stored in browser, sent with every request
[ ] Sessions — server-side state, session ID in cookie
[ ] Tokens (JWT) — stateless, self-contained, signed

APIs and Real-time ★★★
[ ] REST APIs

[ ] WebSockets                                                     ★★★

Other Application Protocols ★★

MODULE 12 — CRYPTOGRAPHY AND SECURE PROTOCOLS             ★★★
================================================================

Fundamentals ★★★
[ ] Security goals: Confidentiality, Integrity, Authentication, Non-repudiation
[ ] Plaintext → Encrypt (key) → Ciphertext → Decrypt (key) → Plaintext

Encryption ★★★
[ ] Symmetric Encryption — same key for encrypt and decrypt
      Fast, used for bulk data
      AES (Advanced Encryption Standard) — most common today
      DES — old, broken, 56-bit key
      Key distribution problem: how to share the key securely?
[ ] Asymmetric Cryptography — public key + private key pair
      Public key: anyone can have it (encrypt or verify)
      Private key: only owner has it (decrypt or sign)
      RSA — most common asymmetric algorithm
      Slow — used only for key exchange, not bulk data
[ ] Diffie-Hellman Key Exchange                                   ★★★
      Two parties agree on shared secret over insecure channel
      Neither side sends the secret directly
      Foundation of forward secrecy in TLS
[ ] Hybrid Encryption — asymmetric for key exchange, symmetric for data
      Used in TLS, HTTPS

Hashing ★★★
[ ] Hash Functions — one-way, fixed output length
      MD5 (broken), SHA-1 (deprecated), SHA-256, SHA-3
      Same input → always same hash
      Tiny change in input → completely different hash (avalanche effect)
      Cannot reverse hash to get input
[ ] MAC (Message Authentication Code) — hash + secret key
      Verifies integrity AND authenticity
[ ] HMAC — Hash-based MAC (industry standard)
[ ] Digital Signatures                                            ★★★
      Sign: hash the message, encrypt hash with PRIVATE key
      Verify: decrypt with PUBLIC key, compare with hash of message
      Provides: integrity + authentication + non-repudiation

PKI and Certificates ★★★
[ ] Certificate Authority (CA) — trusted third party that signs certificates
[ ] Certificate contains: public key + identity + CA signature
[ ] Chain of Trust: Root CA → Intermediate CA → End Certificate
[ ] Browser verifies certificate before trusting HTTPS site
[ ] PKI — Public Key Infrastructure (system of CAs and certificates)
[ ] Certificate Pinning — app hardcodes expected certificate (prevents MITM)

TLS ★★★
[ ] TLS (Transport Layer Security) — successor to SSL (SSL is broken/deprecated)
[ ] TLS Handshake (know this step by step — Cisco will ask)
      1. ClientHello: TLS version, cipher suites, random nonce
      2. ServerHello: chosen cipher, server random, certificate
      3. Client verifies certificate (CA chain)
      4. Key Exchange: Diffie-Hellman ephemeral (ECDHE)
      5. Both derive session keys from shared secret + randoms
      6. ChangeCipherSpec + Finished (both sides)
      7. Encrypted communication begins
[ ] Forward Secrecy — session key derived fresh each time
      Even if private key leaked later, past sessions cannot be decrypted

Metrics ★★★
[ ] Latency — time for one packet to travel source → destination
[ ] Bandwidth — maximum data rate on a link
[ ] Throughput — actual data rate achieved
[ ] RTT (Round Trip Time) — latency × 2 (there and back)
[ ] TTFB (Time to First Byte) — when browser gets first byte of response
[ ] Jitter — variation in latency (bad for video/voice)
[ ] Packet Loss — % of packets that don't arrive

[ ] Latency Sources and Delays
      Propagation delay — speed of signal in medium
      Transmission delay — time to put bits on wire (size/bandwidth)
      Processing delay — time router takes to process header
      Queuing delay — time waiting in router buffer
[ ] Congestion and Bufferbloat
[ ] QoS — Quality of Service (prioritize traffic types)

Rate Limiting ★★★
[ ] What is rate limiting? — limit requests per time window
[ ] Fixed Window Counter — simple, edge case at window boundary
[ ] Sliding Window Log — accurate, high memory
[ ] Sliding Window Counter — approximate, memory efficient
[ ] Token Bucket — tokens added at fixed rate, burst allowed
[ ] Leaky Bucket — output at fixed rate, smooths bursts
[ ] Token Bucket vs Leaky Bucket — burst handling difference
[ ] Concurrency Limiter — limit simultaneous connections

Load Balancing ★★★
[ ] What is a Load Balancer? — distributes traffic across servers
[ ] L4 Load Balancer — routes by IP/port, fast, no content inspection
[ ] L7 Load Balancer — routes by URL/headers/cookies, smart routing
[ ] Load Balancing Algorithms
      Round Robin — requests distributed equally in order
      Weighted Round Robin — more traffic to stronger servers
      Least Connections — send to server with fewest active connections
      IP Hash — same client always goes to same server (sticky sessions)
      Random — random server selection
[ ] Health checks — LB removes unhealthy servers automatically

CDN ★★★
[ ] CDN — Content Delivery Network
      Caches static content at edge nodes near users
      Reduces latency, origin server load, bandwidth
[ ] CDN Cache Lifecycle — origin pull, TTL, cache invalidation
[ ] How DNS routes to nearest CDN node (anycast or GeoDNS)

MODULE 15 — SITUATION-BASED (THE FINAL GOAL)             ★★★
================================================================

These 4 scenarios test whether you understand everything holistically.
Prepare a clear verbal answer for each — interview gold.

[ ] SCENARIO 1: What happens when you type google.com and press Enter?
      DNS resolution → TCP connection → TLS handshake →
      HTTP request → Server processes → HTTP response →
      Browser renders page
      (Full flow: every layer of OSI in action)

[ ] SCENARIO 2: What happens when DNS fails?
      Browser cache miss → OS cache miss → Resolver fails →
      Timeout → Cannot resolve → Connection refused
      Fallback: /etc/hosts file, secondary DNS server

[ ] SCENARIO 3: What happens when you connect to public Wi-Fi?
      DHCP: get IP, gateway, DNS
      Security risks: MITM, evil twin, packet sniffing
      Why HTTPS protects you even on untrusted network
      VPN as extra protection

[ ] SCENARIO 4: How does a CDN serve an image/video?
      User DNS request → CDN DNS (GeoDNS/anycast) → nearest edge node
      Cache hit: serve immediately
      Cache miss: fetch from origin, cache, serve
      TTL expiry → re-fetch
